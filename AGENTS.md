# AGENTS

Standing operating rules for any AI coding agent working in this repository. Applies to
every task regardless of who asks or how it's phrased.

Start with `HANDOVER.md` (current state and open questions), `README.md` (what ships, the
API, the worker and its env) and `docs/RUNBOOK.md` (launchd services, restart, queue
admin, troubleshooting, smoke scripts). The app-server (`127.0.0.1:7860`) and the queue
worker run live from this clone under launchd: do not restart them, trigger a render, or
call a write endpoint unless that is the task.

## AI Attribution & Branding Policy (non-negotiable, owner directive 2026-07-31)

Every AI system used in this repo or its development workflow — Claude, GPT/Codex,
Gemini, Grok, Copilot, Cursor, Windsurf, Cline, Aider, Devin, or any other current or
future coding assistant, agent, IDE extension, MCP server, or orchestration layer — is
internal tooling only. Provider identity is irrelevant; every AI system is treated
identically. None of them are authors, contributors, reviewers, maintainers, or brands,
anywhere this repo's code, history, or product surface is visible. This applies
regardless of how a request is phrased or how small the change seems; a tool's own
default behavior is not a valid reason to violate it.

- **Commits:** no `Co-Authored-By: <assistant>`, session-link trailer, or model/provider
  name in the message. Describe the change and its reasoning only.
- **Branches:** never prefixed with an assistant's name (e.g. `claude/...`). If a
  harness auto-creates one at session start, move real work onto a plain
  `feature/…`/`fix/…`/`chore/…` branch before it accumulates commits.
- **Pull requests & issues:** titles/bodies/comments describe the work only — no
  "generated by," "co-authored by," or session-link footers. Edit them out immediately
  if a platform auto-appends one; a PR body remains editable even after merge.
- **Code reviews:** no AI identified as reviewer/author/approver — technical content
  only.
- **Source code:** no generated-by comments, banners, or annotations in any language.
- **Documentation, UI copy, API responses:** neutral terms only, except where the doc is
  specifically about AI integration itself. No `generatedBy`/`model`/`provider`/`agent`
  fields in API responses unless functionally required.
- **Logs, configuration, package metadata, CI/CD, generated assets:** no model/provider
  names, generation signatures, or AI listed as author/maintainer in any of these.
  Provider identifiers used strictly for functional integration (API endpoints, model
  selection, auth) are permitted — that's operational configuration, not attribution.
- **Retroactive:** if AI branding turns up in tracked files, PR bodies, or reachable
  history during unrelated work, fix it as part of that work, or flag it if genuinely
  out of scope.
- **Known, verified, unfixable-from-inside-the-repo limitation:** a PR opened through
  the Claude Code GitHub App carries a platform-level "via Claude" badge
  (`performed_via_github_app` in the GitHub API) that isn't part of the PR body/commits
  and isn't editable from inside the repo.
- **Known pre-existing item, not yet addressed:** six commits in reachable history carry
  an AI `Co-Authored-By` trailer: c458a5e, 319892f, ea9e6bd, a63cfc6 and c20f7d9
  (2026-08-14, after this policy) and 8bccce7 (2026-07-03, before it). Removing them
  means rewriting published history; get explicit confirmation from the repo owner
  first, never as a side effect of unrelated work.
- **The one exception:** honest self-disclosure when a human directly asks "are you an
  AI" / "which model is this," or when legal/contractual/compliance disclosure is
  required. This bans unsolicited branding, not truthful disclosure.

## Contract-first rule (fleet, enforced since 2026-09-08)

Any change to a route, Mongo collection, env var or outbound host must update
its contract doc and regenerate `docs/_audit/*.json` in the same commit:
`python3 scripts/fleet-audit-inventory.py --write`, then `--check`. CI runs
`--check` and fails on drift. Full rule: `docs/_audit/contract-first-rule.md`.
Cross-app contract: `docs/TRYON_ATLAS_CONTRACT.md`; routes:
`docs/_audit/api-reference.md`.

## Local gates

What CI runs (`.github/workflows/ci.yml`), plus the checks CI cannot run:

```bash
python3 -m compileall -q app.py model_paths.py services scripts studio_tools tests
python3 scripts/fleet-audit-inventory.py --check
./.venv311/bin/python -m pytest -q tests
./.venv311/bin/python scripts/smoke_local_api_fencing.py   # all six: docs/RUNBOOK.md
```

CI also runs a gitleaks secret scan of the working tree. The compile, inventory and
smoke checks need neither the running services nor Atlas, and none of them renders.
